# Φάση 1 — Θεμέλια: αναφορά

## Τι ολοκληρώθηκε

**Υποδομή**
- Monorepo με git (`apps/manager`, `services/api`, `packages/shared`), pnpm workspaces.
- Dockerfile (ένα image: API + Flutter web), `docker-compose.yml` με Postgres, nightly backups και Cloudflare Tunnel.
- GitHub Actions: typecheck, tests (API σε πραγματική Postgres, Flutter), έλεγχος ότι τα generated μοντέλα είναι
  ενημερωμένα, build & push image στο GHCR. Dependabot για npm, pub, actions, docker.

**Βάση & API**
- PostgreSQL schema για όλες τις υπάρχουσες οντότητες, με χρήματα σε cents και UUIDs, μέσα από migrations
  και seed με δοκιμαστικά δεδομένα και έναν χρήστη ανά ρόλο.
- Auth: email + κωδικός, **μόνο με πρόσκληση**, ορισμός κωδικού από link, επαναφορά κωδικού, TOTP 2FA
  **υποχρεωτικό για admin / manager / λογιστή / social media manager**, εφεδρικοί κωδικοί, «να με θυμάσαι 30 μέρες».
- 7 ρόλοι με πίνακα δικαιωμάτων, ελεγχόμενοι server-side σε κάθε endpoint. Ένας χρήστης μπορεί να έχει πολλούς ρόλους.
- Audit log για κάθε αλλαγή (ποιος, τι, πριν/μετά). Είναι append-only και κλειδωμένο με trigger στη βάση.
- Ευαίσθητα στοιχεία μελών (ΑΦΜ, ΑΜΚΑ, IBAN, διαβατήριο κ.λπ.): κρυπτογραφημένα, ορατά μόνο στον admin,
  και κάθε προβολή καταγράφεται.
- **Κοινόχρηστο ημερολόγιο**: κάθε χρήστης παίρνει προσωπικό σύνδεσμο iCal για Google, Apple ή Outlook
  (lives + εκδηλώσεις ομάδας + τα δικά του ιδιωτικά). Ο σύνδεσμος ανανεώνεται ή απενεργοποιείται από το app.
  Υπάρχουν και ιδιωτικές εκδηλώσεις (π.χ. «δεν είμαι διαθέσιμος»).
- Οι εικόνες προϊόντων ανεβαίνουν στον server και ελέγχεται ότι είναι πραγματικές εικόνες.

**Flutter app**
- Οι οθόνες έμειναν ίδιες στη δομή. Τα δεδομένα έρχονται πλέον από τον server και είναι κοινά για όλους.
  Το `localStorage` δεν χρησιμοποιείται για δεδομένα.
- Πραγματική οθόνη σύνδεσης, βήμα 2FA, οδηγός ενεργοποίησης 2FA με QR, αποσύνδεση.
- Νέα σελίδα **Menu → Χρήστες** (μόνο για admin): πρόσκληση, ρόλοι, απενεργοποίηση, αποσύνδεση από όλες τις συσκευές.
- Το UI κρύβει ό,τι δεν επιτρέπει ο ρόλος. Ο διακόπτης «Admin» στα Settings καταργήθηκε.
- Υποδομή μεταφράσεων EL/EN, με επιλογή γλώσσας που αποθηκεύεται στον λογαριασμό.
- Διορθώθηκαν από το audit:
  - τα χρήματα από `double` σε cents,
  - τα αριθμοί παραγγελιών (τώρα δίνονται από τον server: #1001, #1002…),
  - το crash όταν λείπει προϊόν ή πελάτης,
  - η λίστα streaming που αγνοούνταν,
  - το test που αποτύγχανε.
- Τα μερίδια ενοικίου αθροίζουν πλέον ακριβώς στο σύνολο (350 € / 11 = 2 × 31,82 + 9 × 31,81).

## Πώς το δοκιμάζεις

```bash
pnpm install && cp .env.example .env     # + τα 2 secrets (βλ. README)
pnpm --filter @tbn/shared build && pnpm db:migrate && pnpm db:seed
cd apps/manager && flutter build web && cd ../..
WEB_APP_DIR=apps/manager/build/web pnpm dev
```

Άνοιξε το http://localhost:8080. Οι χρήστες είναι `member@tbn.local`, `admin@tbn.local` κ.λπ., με κωδικό
`tbn-dev-password`.
- Ως **member**: βλέπεις τα πάντα εκτός από πελάτες και ευαίσθητα στοιχεία, και δεν μπορείς να αλλάξεις lives.
- Ως **admin**: σου ζητείται πρώτα 2FA. Χρειάζεσαι μια εφαρμογή authenticator. Τα emails (προσκλήσεις,
  επαναφορά) εμφανίζονται στο terminal του API.

Tests: `pnpm -r test` (API και shared: 33 + 28) και `cd apps/manager && flutter test` (26).

## Επαλήθευση

- **API**: integration tests σε πραγματική Postgres για auth, 2FA, προσκλήσεις, απενεργοποίηση, ρόλους, CSRF/Origin,
  audit, ιδιωτικά events, κρυπτογράφηση, iCal και εικόνες. Επιπλέον contract test, που στέλνει στο API ακριβώς
  το JSON που παράγει το Flutter.
- **Mutation checks**: όταν απενεργοποίησα σκόπιμα την επιβολή 2FA ή τη μετατροπή ημερομηνιών, τα tests απέτυχαν
  όπως έπρεπε.
- **Browser (Chromium)**:
  - σύνδεση ως member: αρχική, μενού με τα σωστά στοιχεία, χωρίς σφάλματα δικτύου,
  - σύνδεση ως admin: υποχρεωτική ρύθμιση 2FA με QR, επαλήθευση κωδικού, εφεδρικοί κωδικοί,
  - δημιουργία ιδιωτικής εκδήλωσης από το UI. Αυτή η δοκιμή βρήκε bug (500 σε timestamps), το οποίο διορθώθηκε
    και καλύπτεται πλέον από test.

## Τι **δεν** επαληθεύτηκε εδώ

- **Build του Docker image.** Το περιβάλλον μου δεν μπορεί να κατεβάσει base images (Docker Hub 429). Έλεγξα
  ξεχωριστά τα βήματά του (production bundle του API, Flutter web build, `docker compose config`), αλλά το πρώτο
  πραγματικό build θα γίνει στο GitHub Actions.
- **Το GitHub Actions workflow δεν έχει τρέξει ακόμη**, γιατί δεν υπάρχει ακόμη GitHub repo.
- **Το native iOS build** (η λογική για cookies και Keychain υπάρχει, αλλά δεν δοκιμάστηκε σε συσκευή).
- **Αποστολή πραγματικών emails** (SMTP). Στην ανάπτυξη τα emails τυπώνονται στο log.

## Εκκρεμότητες / γνωστοί περιορισμοί

- **Μεταφράσεις**: μεταφράστηκαν το shell, η σύνδεση, το 2FA, οι Ρυθμίσεις και οι Χρήστες. Οι οθόνες των modules
  είναι ακόμη στα ελληνικά και θα μεταφραστούν όταν ξαναδουλευτεί το κάθε module (Merch στη Φάση 2 κ.ο.κ.).
- **Ταυτόχρονες αλλαγές**: αν δύο χρήστες αλλάξουν την ίδια εγγραφή ταυτόχρονα, ισχύει η τελευταία αλλαγή
  (last-write-wins). Το audit log δείχνει και τις δύο.
- **Συγχρονισμός ημερολογίου προς μία κατεύθυνση**: app → προσωπικό ημερολόγιο (iCal). Για την αντίθετη
  κατεύθυνση, ώστε το προσωπικό ημερολόγιο να δείχνει τη διαθεσιμότητα στην ομάδα, χρειάζεται σύνδεση με
  Google Calendar (OAuth). Προτείνω να γίνει στη Φάση 5 (Bookings, διαθεσιμότητα μελών) και θα σε ρωτήσω πριν.
- **Offline**: το app χρειάζεται σύνδεση. Η λειτουργία offline θα υπάρξει μόνο για το POS (Φάση 2).
- **Τα 11 «άτομα ενοικίου»** είναι ακόμη ξεχωριστή λίστα από μέλη και χρήστες. Θα ενοποιηθούν στα Οικονομικά (Φάση 6).
- **Native iOS με Cloudflare Access**: απαιτεί εξαίρεση (bypass) για το `/api` (βλ. OPERATIONS §5).

## Αποφάσεις που πήρα (μικρές, αναστρέψιμες)

- Κωδικοί τουλάχιστον 12 χαρακτήρων. Τα links πρόσκλησης και επαναφοράς λήγουν σε 48 ώρες. Η σύνδεση κρατά 14 μέρες.
- Πίνακας δικαιωμάτων (`packages/shared/src/roles.ts`), τον οποίο μπορείς να αλλάξεις:
  - ο **member** βλέπει οικονομικά και παραγγελίες, αλλά όχι πελάτες (GDPR),
  - ο **manager** επεξεργάζεται τα πάντα εκτός από χρήστες και ευαίσθητα στοιχεία, και δεν διαγράφει,
  - διαγραφές κάνει μόνο ο **admin**,
  - εξαίρεση: ο καθένας διαγράφει τις δικές του εκδηλώσεις.
- Στο Ημερολόγιο, το κουμπί «Πρόβα» έγινε «Νέο» (τίτλος + επιλογή «Ιδιωτικό»).
- Οι διαδρομές OSRM και η αναζήτηση πόλεων συνεχίζουν να καλούνται απευθείας από το app. Θα μεταφερθούν
  πίσω από το API, με cache, στη Φάση 5.
